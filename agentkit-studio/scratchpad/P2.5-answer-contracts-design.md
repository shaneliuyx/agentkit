# P2.5 — Answer contracts + closed-loop recovery (spec)

**Date:** 2026-07-11 · **Follows:** P2 (`85e7af9`/`798bd6b`) · **Risk:** medium-high (FRAME schema + measurement rewrite + a research recovery loop) · **Design input:** codex `codex_p2_discuss3.md`

## Objective

A report **resolves** every research question: answered-with-evidence OR
honestly-declared-unanswerable (with a *logged failed-recovery trace*, never a free
escape). Measurement is deterministic **contract fulfillment**, not lexical overlap.

## Why (from the P2 live run, 3/5)

Two distinct failures: a MEASUREMENT miss (lexical stem-overlap scored a genuinely-
answered Q at 0) and a REAL research gap (a design Q had one thin claim). Codex's
key move: don't classify question type after the fact ("brittle taxonomy theater") —
give each question a **resolution contract at decomposition time**, then measure
whether the promised artifact appeared AND consumed evidence.

## Design

### Contract schema (replaces the bare `dict[str, list[str]]` questions)

`_extract_question_contracts(client, requirement, subjects) -> list[Contract]`, each:
```
{ question:      str,
  subject:       str | "__joint__",
  answer_form:   "claim" | "comparison" | "design" | "code" | "definition",
  min_evidence:  int,          # distinct evidence-backed claims/citations required
  target_section: str }        # the skeleton section it must land in
```
LLM-generated with the question; deterministically validated (form ∈ enum, min_evidence
1–5, subject known-or-`__joint__`, question ≤ `_MAX_QUESTION_WORDS`). Fail-open `[]`
→ P2's subject-generic behavior, byte-identical. `_subject_queries` derives its query
strings from `contract.question` exactly as today (P2 unchanged).

### Phase A — contracts at FRAME
`_extract_question_contracts`; `questions` dict for search derived from contracts
(`{subject: [c.question]}`). Everything downstream of search unchanged in Phase A.

### Phase B — contract-fulfillment measurement (replaces lexical `_question_coverage`)
`_resolve_question_contracts(contracts, artifact_text, claims, sections) -> list[dict]`.
A contract is **resolved** iff:
- its `answer_form` artifact is present in `target_section` (code→a grounded fenced
  block; design→the integration diagram/section; comparison→the comparison table;
  claim/definition→≥1 body-cited claim tagged to its subject), **AND**
- that section cites ≥ `min_evidence` distinct evidence URLs (the substance guard —
  "exists but empty" fails; codex risk (d)).

Deterministic; no lexical similarity, no post-hoc classifier, no embeddings. Recorded
in `coverage.json __questions__` as `{q, subject, form, resolved, mode, evidence}`.

### Phase C — closed-loop recovery + honest gap
Between CLAIMS and WRITE, an **evidence-sufficiency** pre-check (claim-level, not
artifact-level): each contract needs ≥ `min_evidence` answering claims to be writable.
For each under-evidenced question:
1. ONE targeted recovery search (`contract.question` + subject descriptor), reusing the
   `_run_query` gates; re-extract claims tagged the subject; merge.
2. Re-check. Still under-evidenced → mark `recovery_failed` with a trace
   `{queries_tried, sources_fetched, still_short_by}`.
`recovery_failed` questions get a **Limitations line** built from the trace (extends
P4 `_limitations_note` from subjects to questions) — the ONLY path to "declared gap",
so Limitations is never a free escape (codex guard (a)).

## Test plan
- A: contract validation (form enum, min_evidence clamp, unknown-subject→joint, fail-open); query-derivation unchanged (byte-identical regression).
- B: `_resolve_question_contracts` — code-form resolved by a grounded fence + ≥N cites; design-form by the diagram; claim-form by a cited claim; "section exists but 0 cites" → NOT resolved (substance guard); wrong target_section → not resolved.
- C: recovery fires only for under-evidenced Q; merges recovered claims; `recovery_failed` emits a trace + a Limitations line; a resolved-on-first-pass Q triggers NO recovery (no wasted search).
- Live: the Pi/Craft run — each of 5 Qs resolved OR a traced Limitation; the design Q resolved by the diagram (was a false ✗ under lexical); no fabricated filler.

## Guards against gaming (codex (d))
- `min_evidence` citation floor = substance, not formatting.
- Limitations requires a failed-recovery trace = no cheap escape.
- Recovery is claim-grounded (reuses offtopic/anchor gates) = no relevant-looking filler.

## Non-goals
- Embedding/LLM-judge measurement (contract-fulfillment is deterministic; not needed).
- >1 recovery round (bounded; a 2nd round is a future call if live shows need).
